# Voreli

Self-hosted платформа общения в реальном времени: голосовые каналы, демонстрация экрана,
текстовый чат с картинками и файлами. Разворачивается на своей инфраструктуре — данные
остаются у тебя.

> Проект в разработке. Публичного релиза пока нет.
>
> **Что уже работает:** регистрация по приглашению, серверы с категориями и каналами,
> роли и права, текстовый чат в реальном времени с историей, «печатает» и непрочитанными.
> **Чего ещё нет:** голоса и демонстрации экрана — это следующий этап.

## Что это

Voreli решает ту же задачу, что Discord, но в границах, которые ты контролируешь сам:
свой сервер, своя база, свой SFU. Никаких сторонних сервисов в тракте медиа.

Основные сценарии:

- **Голосовые каналы** — постоянные комнаты, куда заходишь и выходишь, а не звонки
- **Демонстрация экрана** — с системным звуком, несколько зрителей одновременно
- **Текстовые каналы** — история, ответы на сообщения, реакции, вложения и картинки
- **Звонки один на один** — с настройкой под слабый канал: аудио по умолчанию, низкий
  битрейт, переподключение без разрыва разговора. Работают в мобильном браузере
- **Роли и права** — кто какие каналы видит, кто может говорить, кто модерирует

## Технологии

| Слой | Выбор |
|---|---|
| Медиа | [mediasoup](https://mediasoup.org/) — SFU, голос и видео через сервер |
| Бэкенд | NestJS (TypeScript), Socket.IO для сигналинга и чата |
| Данные | PostgreSQL + Prisma, Redis для presence и состояния голоса |
| Файлы | S3-совместимое хранилище |
| Клиент | React + TypeScript, Vite, Zustand, Tailwind CSS |
| Десктоп | Tauri 2 — позже, поверх того же клиента |
| Монорепо | pnpm workspaces + Turborepo |

Почему SFU, а не P2P: при P2P каждый участник шлёт свой поток каждому, и на пятом
человеке канал пользователя заканчивается. SFU принимает один поток и раздаёт остальным.

## Структура

```
apps/
  server/    NestJS: API, WebSocket-шлюз, mediasoup SFU
  web/       React SPA — основной клиент
packages/
  shared/    типы и контракты, общие для сервера и клиента
```

Один репозиторий, несколько пакетов. Контракты WebSocket-событий лежат в `packages/shared`
и импортируются обеими сторонами — поэтому клиент и сервер не могут разъехаться незаметно.
Собираются и деплоятся они при этом независимо.

## Планы

Позже, после того как голос и права устоятся:

- **боты** — автоматизация и запись разговоров;
- **запись и транскрипция** — SFU видит аудио по дорожке на участника, поэтому транскрипт
  получается с разметкой «кто что сказал». Только с явным согласием участников и
  индикатором записи;
- **MCP-сервер** — доступ AI-агентов к транскриптам и истории чата в пределах прав
  пользователя;
- **сквозное шифрование** сообщений и голоса. Запись при этом возможна только через бота,
  который является явным участником разговора и виден всем — тайно записать нельзя
  технически, а не по договорённости;
- десктоп на Tauri 2.

## Запуск

Требуется Node 22+, pnpm 10+, Docker.

```bash
cp .env.example .env      # задать JWT_SECRET; порты можно сдвинуть, если заняты
pnpm install
docker compose up -d      # postgres, redis, minio
pnpm db:migrate           # схема базы
pnpm dev                  # сервер и клиент параллельно
```

Клиент поднимется на `http://localhost:5173` и покажет форму входа. Проверить сервер
напрямую: `curl http://localhost:3000/health`.

Зарегистрироваться можно только по приглашению — это осознанное решение, а не недоделка.
Первое приглашение создаётся вручную: заведите сервер и код приглашения в базе
(`pnpm db:studio`), дальше приглашения выдаются из интерфейса.

Полезное: `pnpm verify` — линт, проверка типов и тесты одной командой. Тесты идут на
**реальном** Postgres, поэтому им нужна отдельная база и переменная `DATABASE_URL_TEST` —
см. `.env.example`.
